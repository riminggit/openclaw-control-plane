# 03 — 非功能需求

## 3.1 性能要求

| ID     | 要求                                 | 目标值                   | 衡量方式                 |
| ------ | ------------------------------------ | ------------------------ | ------------------------ |
| NFR-P1 | 编排调度延迟 P95                     | < 500ms（不含 LLM 调用） | 控制面 API 响应时间      |
| NFR-P2 | 检查点写入延迟                       | < 200ms                  | 从状态变更到检查点持久化 |
| NFR-P3 | 检查点恢复时间                       | < 5s                     | 从检查点恢复到继续执行   |
| NFR-P4 | WebSocket 消息推送延迟               | < 100ms                  | 从事件发生到客户端接收   |
| NFR-P5 | MCP 工具发现延迟                     | < 2s                     | 从连接到工具列表获取     |
| NFR-P6 | 单实例 500+ Subtask 时列表与图仍可用 | 分页/懒加载              | 前端渲染时间 < 3s        |
| NFR-P7 | 上下文压缩执行时间                   | < 3s                     | Auto-compact 单次执行    |
| NFR-P8 | 成本追踪记录延迟                     | < 50ms                   | 异步写入，不阻塞主流程   |

---

## 3.2 安全要求

| ID     | 要求                       | 实现方式                              |
| ------ | -------------------------- | ------------------------------------- |
| NFR-S1 | 工具与命令权限默认拒绝     | 显式 allowlist，ToolContext 校验      |
| NFR-S2 | 审计日志不可篡改           | 追加写入（append-only），独立存储     |
| NFR-S3 | Agent 文件系统访问权限控制 | 沙箱隔离 + 路径白名单                 |
| NFR-S4 | MCP 工具执行权限控制       | 按步骤配置 allowlist/denylist         |
| NFR-S5 | 多租户数据隔离             | tenant_id 贯穿所有查询                |
| NFR-S6 | API Key / JWT 安全         | 继承现有认证体系，扩展 Agent 级 token |
| NFR-S7 | 敏感信息脱敏               | 日志中自动脱敏 API Key、token         |
| NFR-S8 | Agent 通信加密             | WebSocket WSS + 消息签名              |

## 3.4 可观测性要求

| ID     | 要求           | 实现方式                                       |
| ------ | -------------- | ---------------------------------------------- |
| NFR-O1 | 统一 Event Log | 步骤状态变更、工具调用、审核记录、Gateway 回执 |
| NFR-O2 | 结构化日志     | JSON 格式，包含 trace_id、span_id              |
| NFR-O3 | 指标采集       | Prometheus 格式：调度延迟、token 使用、成本    |
| NFR-O4 | 分布式追踪     | OpenTelemetry 集成                             |
| NFR-O5 | 实时仪表盘     | 前端 Dashboard 展示关键指标                    |
| NFR-O6 | 告警机制       | 成本超限、步骤超时、Agent 异常自动告警         |

## 3.5 兼容性要求

| ID     | 要求                 | 实现方式                                              |
| ------ | -------------------- | ----------------------------------------------------- |
| NFR-C1 | v1 API 向后兼容      | 破坏性变更走 /api/v2，旧版并存至少一个 minor 周期     |
| NFR-C2 | 数据 Schema 只增不删 | 优先 additive 迁移；删列走多阶段                      |
| NFR-C3 | 模板版本化           | WorkflowTemplateVersion，实例锁定创建时快照           |
| NFR-C4 | 运行时契约版本       | runtime_contract_version 字段                         |
| NFR-C5 | 编排 Profile         | orchestration_profile 字段，新能力通过新 profile 引入 |
| NFR-C6 | 特性开关             | 全局或按租户控制新功能启用                            |
| NFR-C7 | 契约测试             | CI 中对比破坏性 diff，发布门禁                        |

---

## 3.6 可靠性要求

| ID     | 要求        | 实现方式                                  |
| ------ | ----------- | ----------------------------------------- |
| NFR-R1 | 步骤级 memo | 每个可重试步骤持久化 input_hash、输出摘要 |
| NFR-R2 | 失败恢复    | 从最近一致检查点恢复，禁止默认全量重跑    |
| NFR-R3 | 幂等执行    | 每个步骤携带 idempotency_key              |
| NFR-R4 | 重试策略    | 可配置重试次数、退避策略                  |
| NFR-R5 | 超时控制    | 步骤级 + 工作流级超时                     |
| NFR-R6 | 优雅降级    | Agent 不可用时自动降级到备用 Agent        |
